# Batch Processing

Process multiple documents at once with DocuLock's batch upload and verification capabilities. Upload entire folders or ZIP archives and process hundreds of documents efficiently using Programmable Transaction Blocks (PTB).

<Callout type="success">
  Batch processing uses Sui's Programmable Transaction Blocks (PTB) to store multiple documents in a single atomic transaction.
</Callout>

## Overview [#overview]

Batch processing enables:

- **Multi-file Upload**: Select individual files, entire folders, or ZIP archives
- **Parallel Hashing**: Web Workers enable concurrent hash calculation
- **Progress Tracking**: Real-time progress bar for each file
- **Atomic Transactions**: All documents stored together or not at all
- **Cost Efficiency**: Lower gas cost per document

## Getting Started [#getting-started]

### Access Batch Upload

1. Navigate to the **Upload** tab
2. Click **"Batch"** mode toggle

### Step 2: Hash Calculation

Automatic parallel hashing:

```
File Queue
    ↓
Web Workers (Parallel)
    ↓
Calculate SHA-256 Hashes
    ↓
Progress Tracking
```

Features:
- **Concurrent processing** - Multiple files hashed simultaneously
- **Progress updates** - Real-time status for each file
- **Error handling** - Individual failures don't stop others
- **Memory management** - Efficient large file handling

### Step 3: Review and Confirm

Review before storing:

- **Total files** - Count of documents
- **Ready to store** - Valid documents
- **Hash errors** - Failed calculations
- **File list** - All files with details

### Step 4: Store with PTB

Execute batch transaction:

```typescript
// Programmable Transaction Block
{
  kind: "moveCall",
  target: "package::module::function",
  arguments: [
    // Document 1
    { hash: bytes, name: "file1.pdf", size: 1024, type: "application/pdf" },
    // Document 2
    { hash: bytes, name: "file2.png", size: 2048, type: "image/png" },
    // ... more documents
  ]
}
```

<Callout type="warning">
  All documents in the batch succeed or fail together. This atomic property ensures consistency.
</Callout>

## PTB Benefits [#ptb-benefits]

### Transaction Efficiency

| Feature | Individual Uploads | Batch Upload (PTB) |
|---------|-------------------|-------------------|
| **Transactions** | N transactions | 1 transaction |
| **Gas Cost** | N × base cost | ~30% lower total |
| **Signatures** | N signatures | 1 signature |
| **Confirmation** | N confirmations | 1 confirmation |

### Atomicity

- **All succeed or none** - Consistent state
- **Rollback on failure** - No partial uploads
- **Single point of failure** - Easier error handling
- **Deterministic outcome** - Clear success/failure

### Gas Optimization

- **Shared overhead** - Fixed cost split among documents
- **Batch discount** - Per-document savings
- **Predictable cost** - Estimate before submission
- **Cost tracking** - Per-file breakdown

## Error Handling [#error-handling]

### Individual File Errors

Features:

- **Skip and continue** - Other files unaffected
- **Error logging** - Detailed failure reasons
- **Retry capability** - Upload failed files separately
- **Partial success** - Store successful documents

### Common Errors

| Error | Cause | Solution |
|-------|-------|----------|
| **Hash Error** | File corruption | Re-select file |
| **Size Limit** | File too large | Split or compress |
| **Type Error** | Unsupported format | Convert file |
| **Tx Failed** | Network/insufficient gas | Check wallet, retry |

### Transaction Failures

If PTB transaction fails:

1. Review error message
2. Check wallet balance
3. Verify network status
4. Retry batch upload

<Callout type="info">
  Use the "Debug" button to view detailed error information in the browser console.
</Callout>

## Limits and Constraints [#limits-and-constraints]

### Batch Size

Recommended limits:
- **Documents per batch**: Up to 50
- **Total batch size**: Under 100 MB
- **Individual files**: Up to 50 MB

<Callout type="warning">
  Large batches may exceed transaction size limits. Split very large uploads into multiple batches.
</Callout>

### File Type Limits

Supported types:
- PDF documents
- Images (PNG, JPG, GIF, WebP)
- Text files (TXT, MD, JSON)
- Office documents (DOCX, XLSX)

Unsupported types:
- Executables (EXE, APP)
- Archives (except ZIP for extraction)
- Encrypted files
- Binary blobs

## Best Practices [#best-practices]

### For Large Uploads

1. **Split batches** - Groups of 20-30 files
2. **Organize files** - By type or priority
3. **Check sizes** - Before upload
4. **Monitor progress** - Watch for errors

### For Cost Efficiency

1. **Batch similar files** - Optimize gas
2. **Avoid tiny batches** - Minimum 3-5 files
3. **Time uploads** - Low gas periods
4. **Estimate costs** - Before submitting

### For Reliability

1. **Verify hashes** - After storage
2. **Keep records** - Transaction IDs
3. **Test uploads** - Small batches first
4. **Monitor network** - Congestion periods

## Troubleshooting [#troubleshooting]

### Slow Hashing

If hashing is slow:

1. Check browser performance
2. Reduce file sizes
3. Close other tabs
4. Update browser

### Transaction Timeout

If transaction times out:

1. Check network status
2. Verify gas limit
3. Reduce batch size
4. Retry with smaller batch

### Partial Failures

If some files fail:

1. Review error messages
2. Check failed files individually
3. Retry failed files
4. Verify file integrity
